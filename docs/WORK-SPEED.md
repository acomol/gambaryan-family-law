# Как работаем быстро

**Версия:** `WORK-SPEED v1.0.0 | 2026-09-17`

Замер сессии 16–17 сентября: 14 задач Codex — 183 минуты (в среднем 13 на задачу),
23 публикации, 40 коммитов. Половина задач Codex были правкой текста или нескольких строк
CSS: там он стоил 8–10 минут вместо одной. Отсюда правила ниже.

## Кто что делает

| Размер задачи | Кто | Ориентир |
|---|---|---|
| Текст, отступ, цвет, размер, видимость блока (≤ ~20 строк, один-два файла) | оператор сам, быстрым циклом | ≤ 2 мин до снимка владельцу |
| Новый элемент или поведение в одном слое (CSS-компонент, правка скрипта) | оператор сам, если правка понятна; иначе Codex | 5–15 мин |
| Функциональность в нескольких файлах (форма, контракт, тесты), исследование, состязательное ревью | Codex в своей копии | 10–35 мин, параллельно |
| Решение «как это должно выглядеть» | макет на живой странице подменой стилей, 2 варианта владельцу | 3–5 мин |

Параллельность: копии `deck-a`, `deck-b`, `deck-c` — у каждой свои файлы в задании, чтобы
слияние не давало конфликтов. Три задачи одновременно по 7–10 минут вместо 25 подряд.

## Цикл правки

```bash
bash scripts/quick-dev5.sh ".hero__title" 1440,390   # сборка + публикация + сверка + снимки, ~33 с
```

Пропускает standalone, шрифтовые варианты, нумерованный вариант и все гейты — они не
влияют на то, что владелец увидит на `final-dev5`.

```bash
bash scripts/full-checks.sh            # гейты пакетом после серии правок, ~2 мин
bash scripts/full-checks.sh --visual   # + визуальный набор с пересъёмкой эталонов, ~8 мин
```

Точечная проверка вместо полного набора:

```bash
npx playwright test -c tests/visual/playwright.config.ts --no-deps -g "3. Отступы Hero"
```

Снимок и геометрия любого элемента на живом адресе (заявки не создаются):

```bash
python -B scripts/shot.py ".svc-frame" --widths 1440@2,390@3 --click "#svc-tab-3"
```

## Задача для Codex

```bash
bash scripts/codex-task.sh deck-b I:/Temp/.../brief.md              # исполнение
bash scripts/codex-task.sh deck-c I:/Temp/.../brief.md read-only    # ревью, исследование
```

Бриф — файл UTF-8. Обязательные разделы: рабочая копия и ветка; **какие файлы можно трогать**
(остальные заняты другой копией); дословное указание владельца; решения архитектора;
**быстрые гейты** (сборка нужного варианта + свои тесты; полный набор и эталоны — на операторе);
формат отчёта. Чем уже список файлов, тем меньше конфликтов при слиянии.

## Что экономит время владельца

- Несколько замечаний в одном сообщении — один цикл сборки и один набор снимков.
- Спорное оформление: сначала макет на живой странице, потом реализация.
- Прототипы крупных изменений — на отдельный адрес (`wrangler pages deploy … --branch=<имя>`),
  основной `final-dev5` остаётся рабочим.
