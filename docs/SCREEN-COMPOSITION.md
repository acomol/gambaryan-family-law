# Композиция экранов — спецификация и критерии приёмки

> Статус: рабочая спецификация для исполнителей (Codex).
> Приёмку по критериям из этого документа делает ведущий агент сессии.
> База: текущая вёрстка `site/` + best practices лендингов юридических услуг
> (lead-gen: один экран = одна задача, доказательство сразу после обещания,
> путь к конверсии с каждого экрана).

## Сквозные правила

| Параметр | Значение | Откуда |
|---|---|---|
| Контейнер контента | 1200px | `--container` |
| Контейнер hero | 1360px | `--container-hero` |
| Боковой отступ | 24px | `--pad-x` |
| Вертикальный ритм секций | clamp(56px, 8vw, 96px) | `--section-pad` |
| Брейкпоинты | 720 / 860 / 1200 | сложились в вёрстке, не плодить новые |
| Семейства | Onest (текст), Playfair Display (заголовки) | fonts.css — только эти два |
| Тап-таргеты на мобильном | ≥ 44×44px | WCAG 2.5.8 / Apple HIG |
| Размер шрифта в инпутах | ≥ 16px | иначе iOS зумит форму |

Правило чередования фонов: тёмный (hero) → тёмный (факты на #101214) →
кремовый (услуги #f6f1e8) → тёмный (прецедент) → кремовый (адвокаты) →
тёмный (контакты, футер). Два кремовых подряд не ставить — теряется ритм.

Каждый экран заканчивается конверсионной точкой (кнопка или телефон),
но **основной** CTA «Записаться на консультацию» — один на экран.

## Экран 1 — Hero (первый экран, единственный, который видят все)

**Задача:** за 3 секунды ответить «кто это, для кого и что сделать».

**Состав, в порядке приоритета:**
1. Шапка: логотип, навигация (4 пункта), CTA «Получить консультацию»
2. Надстрочник «Адвокатская практика · Тель-Авив» (гео-сигнал)
3. H1 «Адвокат по семейному праву в Израиле» — не длиннее 2 строк на 1440
4. Подзаголовок: предметы споров + 30 лет практики + русский язык (2–3 строки)
5. Пара CTA: основной (wine) + мессенджер (outline). Никогда два основных
6. Телефон текстовой строкой (кликабельный tel:)
7. Фото пары адвокатов — общий студийный кадр (hero-duo-air)
8. Служебный абзац-дисклеймер (мелкий, приглушённый)

**Десктоп (≥1201):**
- Высота: `min-height: clamp(560px, 84vh, 880px)` — как сейчас. Hero не
  обязан занимать ровно 100vh; «хвост» следующей секции в нижней кромке —
  это норма, он сигналит прокрутку.
- Сетка: текстовая колонка ≤640px слева, фигуры в правой трети кадра.
  Лица — в правой верхней четверти экрана, взгляд направлен в камеру.
- Заслон (scrim) гаснет к 70% ширины; лица никогда не затемняются.
- Золотая линия-ограничитель по нижней кромке — оставить, это якорь конца
  экрана.

**Планшет (861–1200):**
- Текстовая колонка сужается до 440px, кадр доводится к правому краю.
- H1 может стать 3-строчным — допустимо, но не 4.

**Мобильный (≤860):**
- Композиция полосами, наложений нет: надстрочник → H1 в рамке из
  волосяных линий → подзаголовок → фото → CTA → телефон → дисклеймер.
- **Критерий первого экрана:** H1 и верх фотографии видны целиком на
  390×740 (viewport iPhone за вычетом браузерного хрома). Основной CTA —
  не глубже полутора экранов (≤1100px от верха документа).
- Фото-полоса: окно 4:3 во всю ширину поверх мобильного кропа 6:5
  (hero-duo-mob), object-position 50% 22% — воздух над головами
  сохраняется, срез уходит снизу с пиджаков. Решение владельца
  2026-08-04: ниже 4:3 не ужимать.
- ВЫПОЛНЕНО (2026-08-04): отступы полос ужаты, надстрочник на мобильном
  скрыт, фото 6:5 → 4:3. Обе CTA-кнопки входят в первый экран целиком
  на 390×740 (замер: основная 611–663, WhatsApp 675–727).

## Экран 2 — Факты («Опыт, который подтверждается фактами»)

**Задача:** доказательство обещания из hero до того, как пользователь
увидит цены/услуги. Порядок «обещание → доказательство» не менять.

**Состав:**
1. Надстрочник винного цвета + H2 + золотая линейка (единый паттерн секций)
2. Три карточки-факта: 30+ лет / 1 прецедент / 900+ публикаций.
   Число — крупно (Playfair не используется, это цифры — Onest 700/800,
   `font-variant-numeric: tabular-nums`), подпись — что это значит,
   абзац — расшифровка
3. Полоса-бар: лицензия № 30178, языки, адрес приёма (микро-доверие)

**Десктоп:** три карточки в ряд, равной высоты (grid, не flex-wrap),
число + единица на одной базовой линии.

**Мобильный (≤860):** карточки в столбик в порядке утверждённого
контента: 30 лет → прецедент → 900 публикаций. Решение владельца
(2026-08-04): порядок НЕ менять, контент берётся из утверждённых
материалов как есть.
Полоса-бар складывается в столбик (уже сделано).

## Экран 3 — Услуги

**Задача:** маршрутизация «моя ситуация → чем помогут» без цен.

**Состав:** H2 + сетка карточек услуг. В карточке: название (Playfair),
2–3 строки описания, аватар ведущего адвоката (подпись «кто ведёт»),
ссылка-якорь на форму с указанием темы.

**Десктоп:** максимум 3 колонки; строки выровнены по сетке.
**Мобильный:** одна колонка; карточка целиком кликабельна (вся область —
ссылка на #contact), не только слово-ссылка.

## Экран 4 — Прецедент (баннер-доказательство)

**Задача:** один сильный кейс, отличающий практику от конкурентов.

**Состав:** карточка на тёмном градиенте с золотой кромкой слева,
надстрочник «Международный прецедент», заголовок курсивным Playfair,
абзац с дисклеймером «каждый случай оценивается отдельно» (юридическая
гигиена — не обещание результата), CTA-пара.

**Десктоп (>1200):** текст слева ≤432px, вырезанная фигура Александра
справа (cutout с альфой), кнопки колонкой справа от текста.
**1200 и уже:** фигура скрывается (уже так), карточка — текст + кнопки.
**Мобильный:** кнопки на всю ширину, золотая кромка остаётся.

## Экран 5 — Адвокаты («Кто ведёт ваше дело»)

**Задача:** персональное доверие. Люди покупают адвоката, не фирму.

**Состав карточки:** фото → имя (Playfair) → роль (надстрочник) →
чек-лист фактов (5 пунктов максимум) → персональный CTA
(«Записаться к Александру / к Юлии»).

**Правило фотографий (после инцидента 2026-08-04):**
- Окно фото — **4:5, height: auto**, никогда фиксированная высота:
  вертикальный портрет в альбомном окне под cover обрезается до головы.
- Оба портрета — с одной съёмки, одинаковый план (по пояс), одинаковая
  геометрия кадра (верх головы ~11% кадра, фигура по центру).
- Исходники — в `docs/source-photos/`, продакшн-нарезка из них скриптами.

**Десктоп:** две карточки в ряд, футер карточки (CTA) прижат к низу
(`flex: 1` на теле — уже сделано), кнопки на одной горизонтали.
**Мобильный:** столбик, фото 4:5 во всю ширину карточки.

## Экран 6 — Контакты + форма

**Задача:** конверсия. Минимум трения.

**Состав:** слева — способы связи (телефон, WhatsApp, приём) списком с
иконками; справа — форма: имя*, телефон*, email (необязательный),
кнопка, юридическая приписка «не отправляйте документы через форму».
Поля «тема обращения» нет — снижает конверсию, тему уточняет офис.

**Десктоп:** две колонки; форма не шире 520px.
**Мобильный:** способы связи ПЕРЕД формой (звонок — основной канал у
аудитории 45+); поля в столбик; кнопка на всю ширину.

**Состояния формы:** success-блок с подтверждением и кнопкой «отправить
ещё», error-блок с телефоном как fallback. Оба уже есть — не терять при
правках.

## Приёмка (обязательный прогон перед сдачей)

1. Скриншоты 360 / 390 / 768 / 1024 / 1280 / 1600 — глазами, не только код.
2. `document.documentElement.scrollWidth === innerWidth` на каждой ширине.
3. Лица не затемнены заслоном и не перекрыты текстом ни на одной ширине.
4. Критерий первого экрана (390×740) из секции Hero.
5. Один основной CTA на экран; каждый экран заканчивается конверсионной
   точкой.
6. Фолбэк-шрифтов нет: `CSS.getPlatformFontsForNode` не возвращает
   семейств вне Onest / Playfair Display.
7. Для live-задач — proof-блок по Definition of Done (commit + push +
   live-readback).
