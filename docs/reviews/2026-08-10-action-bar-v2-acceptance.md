# Приёмка: нижняя панель v2.1.0 и фото адвокатов — HISTORICAL

> Ревью read-only. Код не менялся, деплой не выполнялся.
> Предмет: `594ad8b`, ветка `claude/website-development-kb0fu0`, PR #2.
> Проверяющий — ведущий агент сессии; исполнитель — Codex.

## Как проверялось

Отчёт исполнителя за доказательство не принимался. Источники факта:

1. **Живые адреса через `curl`** — все 9 Preview и боевой.
2. **Браузер (Playwright, 390×844) по зеркалу живых байтов.** Прямой выход
   браузера в интернет в контейнере закрыт (`ERR_CONNECTION_RESET` даже на
   `example.com`), поэтому 51 файл Preview `action-bar` скачан `curl` и
   отдан локальным сервером — тестировались фактически задеплоенные байты.
3. **Таблицы `cmap` шрифтовых файлов** — кириллица проверялась по глифам, а не
   по названию (причина: история с Archivo, `docs/ERRORS.md`).

### Две поправки к собственному стенду

Первый прогон дал 4 FAIL, из них 3 оказались дефектами стенда, а не сайта.
Записано, чтобы этой ошибки не повторяли:

- **404-е и `overflow=29px`** — зеркало было неполным: `srcset`-варианты
  качались не все. После добора (51 файл, 0 промахов) — 0 ошибок, `overflow=0`.
- **«Панель в порядке табуляции»** — проверка через `offsetParent` неверна: она
  не учитывает ни `visibility:hidden`, ни `inert`, а панель отдаёт оба. Замена
  на реальную попытку фокуса дала 0.

Вывод: «FAIL» на неоткалиброванном стенде — не дефект продукта.

## MAJOR-1 — `og:image` живёт на Preview-хосте

На всех 8 Preview `og:url` указывает на боевой `gambarian-landing.pages.dev`, а
`og:image` — на **Preview**-деплой `final-dev.gambarian-landing.pages.dev`.

Воспроизведение:
```bash
curl -s https://action-bar.gambarian-landing.pages.dev/ \
  | grep -oE '<meta property="og:(url|image)"[^>]*>'
```

Чем плохо: Preview-деплои в этом проекте уже удаляли (`hero-c-miniform`,
см. handoff). Удаление `final-dev` ломает карточку ссылки везде, где она
проставлена, включая уже закэшированные Facebook/Telegram/WhatsApp.

Отдельно важна причина, по которой это прошло незамеченным:

| Коммит | Действие |
|---|---|
| `f43d9bc` | добавлен `build-social-preview.py` **с проверкой** «og:url и og:image — один публичный host» |
| `e3bfaa0` | скрипт удалён целиком, вместе с проверкой и её CI-шагом |
| `cc1ea37` | внесён ровно тот дефект, который эта проверка ловила |

Страховку сняли — и через два коммита провалились в неё же.

## MAJOR-2 — на боевом `og:image` относительный

```bash
curl -s https://gambarian-landing.pages.dev/ | grep -oE '<meta property="og:image[^>]*>'
# <meta property="og:image" content="assets/hero-duo-air-1440w.d112fafc.jpg">
```

Open Graph требует абсолютный URL. Карточка боевого адреса, вероятно, не
собирается вообще, и фирменного логотипа на боевом нет — он только на Preview.

**Не регресс этого PR** (боевой намеренно не менялся), но это живая
клиент-facing поверхность, поэтому вынесено в MAJOR.

## MINOR-1 — впустую скачиваемый preload на мобильном

`<link rel="preload" as="image">` тянет **десктопный** кроп
(`hero-duo-air-*`, `imagesizes="100vw"`, без `media`), тогда как `<picture>`
на мобильном отдаёт другой набор по `media="(max-width: 860px)"`
(`hero-duo-mob-*`). Браузер качает ~19 КБ, которые никогда не отрисует, —
и делает это в момент загрузки, конкурируя с реальным hero.

Это единственное консольное предупреждение и единственное расхождение с
отчётом исполнителя («0 ошибок и предупреждений» — предупреждение есть).
Пришло из `6c508dd`, **не регресс** данного PR.

## MINOR-2 — `OPTIONS /api/lead` → 405

Для same-origin отправки формы безразлично, но любой сторонний источник
(или `fetch` с другого origin) упрётся в preflight.

## Замечание к релизу — Function на боевом нет

`GET /api/lead` на боевом отдаёт **200 с HTML** (Function не задеплоена),
на Preview — корректный `405`. Разметка формы указывает `action="/api/lead"`.
При переносе на боевой Function обязана поехать вместе с разметкой, иначе
POST уйдёт в HTML-страницу.

`POST` с телом на Preview даёт `503 temporarily_unavailable` — согласуется с
оговоркой исполнителя про несконфигурированный секрет.
