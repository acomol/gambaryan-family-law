## Что искать

1. **Ложный PASS.** Для каждой проверки придумай состояние дерева, где требование НЕ выполнено, а
   команда проходит, и подтверди возможность этого состояния командой. Частые случаи: grep по
   подстроке, которая есть и в старом тексте; проверка наличия CSS-правила вместо вычисленного
   значения; проверка исходника `site/` вместо собранного `build/variants/final-dev4/`; проверка,
   которая одинаково проходит на final-dev3 и на final-dev4.
2. **Ложный FAIL.** Состояние, где требование выполнено, а команда падает: неразрывный пробел,
   `&nbsp;`, перенос строки внутри искомой фразы, HTML-теги внутри текста, экранирование в grep,
   регистр.
3. **Проверка не того.** Команда измеряет соседний признак вместо заявленного: статус вместо
   содержимого, наличие файла вместо его содержания, `mergeable_state` вместо статуса проверок.
4. **Гейт без негативного теста.** Проверка, которую никто не пробовал уронить намеренно. Назови,
