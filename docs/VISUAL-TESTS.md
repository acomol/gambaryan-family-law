# Визуальная приёмка final-dev4

Document version: `V01`

Last updated: `2026-09-12`

Набор проверяет один лендинг `final-dev4`: секции, восемь услуг, меню,
рабочее время и состояния формы. Числовые требования проверяет код;
утверждение вида выполняет владелец по контактным листам и диффам.
Успешная компиляция или `--list` не означают, что вёрстка прошла приёмку.

## Первый запуск на Windows

PowerShell, из корня рабочей копии, Node.js 24 и Python:

```powershell
git switch codex/final-dev4-s4-hours
git pull --rebase origin codex/final-dev4-s4-hours
npm ci
python -m pip install -r requirements-build.txt
python -B scripts/build-hero-variants.py dev4
npx playwright install chromium
npx tsc --noEmit -p tests/visual
npx playwright test -c tests/visual/playwright.config.ts --list
npm run test:visual:review
npx playwright show-report build/visual-report
```

`test:visual:review` снимает свежие изображения без сравнения с эталонами,
затем собирает контактные листы. Посмотрите PNG в `build/visual-review/`.
Для первого утверждённого набора:

```powershell
npm run test:visual:update
npx playwright show-report build/visual-report
npm run test:visual
git add tests/visual/snapshots
git commit -m "test(visual): approve final-dev4 Windows baselines"
```

Коммит эталонов делается только после просмотра владельцем. Если инвариант
упал, обновление картинки его не исправляет: разберите измерение в отчёте.
Сборщик принимает аргумент `dev4`; остальные Preview для этого набора не нужны.
Локальный `webServer` обслуживает только `build/variants/final-dev4` на
`127.0.0.1:4174`, запрещает HTTP-записи и завершается вместе с Playwright.
Занятый порт можно заменить через `$env:VISUAL_PORT = '4175'`.

Для проверки существующего Preview:

```powershell
$env:BASE_URL = 'https://final-dev4.gambarian-landing.pages.dev/'
npm run test:visual
Remove-Item Env:BASE_URL
```

При `BASE_URL` локальный сервер не запускается. Набор проверяет класс
`page--final-dev4`, чтобы случайно не принять другую страницу. Все запросы
к `/api/lead` перехватываются до навигации; остальные HTTP-записи блокируются.
Формы успеха и сбоя используют `page.route`: 200 `{ok:true}` и 503
`{ok:false,error:'temporarily_unavailable'}`. Настоящих отправок нет.

|---|---:|---:|

| Открытое меню: окно, только ширины ≤860 | 1 на трёх viewport | 3 |
| Два коротких viewport: Hero open/closed | 2 | 4 |
| **Итого свежих снимков / эталонов одной платформы** | | **237** |

Есть 244 зарегистрированных screenshot-теста: семь desktop-сценариев меню
пропускаются. На коротких viewport запускаются также четыре Hero-инварианта
(переполнение, CTA, отступы, изображения); остальные секции туда не включены.

Имя свежего снимка: `<секция>--<состояние>--<ширина>x<высота>.png`.
Эталон: `tests/visual/snapshots/<spec>/<имя>-<platform>.png`, например
`hero--open--360x640-win32.png`. Порог сравнения:
`maxDiffPixelRatio: 0.002`, `threshold: 0.2`.

Детерминизм: `reducedMotion: reduce`, отключённые анимации/переходы,
`animations: disabled`, `caret: hide`, ожидание `document.fonts.ready`,
загрузки и декодирования изображений в снимаемой области. Lazy-изображения
загружаются заранее. Реальный обработчик `[data-business-demo]` переводится
в `data-demo-mode="manual"` и явное `open` даже при совпадении с часами;
в соответствующих сценариях он переключается в `closed`.

## Инварианты и требования владельца

Номера строк ниже относятся к `ACCEPTANCE-MACHINE-FINAL-DEV4.md`;
номера 1–11 слева — к текущему заданию на визуальный набор.

| № | Проверка | Требования / источник |
|---|---|---|
| 1 | `scrollWidth <= clientWidth` на секциях и всех темах | Общий responsive-гейт, 96.5 |
| 2 | CTA целиком внутри 360×600 и 390×740, scrollY=0, без перекрытия | Первый экран, 94.1; текущая короткая матрица |
| 3 | Видимые поля Hero и padding-block контейнеров услуг, адвокатов, консультации, подвала равны `--section-pad` ±2px | 94.4, 94.5 |
| 4 | Высота услуг, координаты/размеры «Ведёт» и CTA ±1px; центр карточки и текста ±2px | 43, 96.3 |
| 5 | Равные рамки фото 4:5; равная desktop-высота карточек | 94.2, 96.2 |
| 6 | Край каждой строки `.hero__note` минимум в 24px от контура фигуры при ≥861px | Текущее требование 6; fixture V01 |
| 7 | Первый текст после каждого пункта меню находится в интервале 0–20px ниже шапки | 96.5; текущий критерий 20px |
| 8 | «тест ДНК» целиком на новой строке через Range | 26 |
| 9 | В closed нет видимых телефонных ссылок, open их восстанавливает, включая меню | 94.3 |
| 10 | Площадь перекрытия переключателем кнопок/ссылок равна нулю в подготовке и консультации | 94.3; текущее требование 10 |
| 11 | Все изображения в кадре загружены; контентные имеют непустой alt | 94.2; текущее требование 11 |

Декоративный повторный портрет `.precedent-photo` в исходной разметке имеет
`alt=""`; только для него пустой alt ожидается. Скрытый переключатель на
мобильном при видимой форме имеет нулевую площадь перекрытия.

Контур перенесён без изменения из `source-contour-v01.json` в
`tests/visual/fixtures/hero-figure-contour.json`: исходник 1440×1002,
погрешность 4 исходных px. Проверка пересчитывает контур с учётом
`object-fit: cover`, `object-position`, рамки и padding; берёт минимальную
границу на всей высоте строки и вычитает погрешность. Неизвестный asset,
неподдерживаемое преобразование или выход за размеченный диапазон дают
ошибку; фикстуру потребуется пересмотреть при смене композиции фотографии.

## Перенос Python-матрицы

`scripts/qa-browser-matrix.py` сохранён вместе с прежним шагом CI.
Проверки final-dev4 распределены между `invariants.spec.ts` и
`python-matrix.spec.ts`: геометрия Hero/CTA/формы, отсутствие переполнения,
клиппинг и иерархия фактов, размеры/стрелки/вкладки/свайп услуг, реальный Onest
через Chromium CDP, ошибки страницы и маркеры сборки, геометрия и видимость
Action Bar, ручное рабочее время и восстановление ссылок после closed.

Только в Python остаются:

- Другие 11 Preview, их шрифты/маркеры, numbered-review и старый аккордеон фактов.
- Effective-width Lora/Literata 345×600/668, специфичные переносы и crop `50% 22%`.
- Ячейки вне новой матрицы: 360×668, 390×724, 720×760, 860×760,
  861×760, 1280×720, 960×760, 961×760, 960×400, 960×401,
  844×390, 2560×1440. В частности, landscape Action Bar и точная граница 960/961.

Python и Node проверяют код обработчика свайпа синтетическими Pointer Events;
нативное поведение жеста на физическом телефоне этим не подтверждается.
Исторические PASS из документа приёмки не считаются новым результатом.

## Контактные листы, отчёт и CI

После сценариев teardown-проект собирает **32 PNG**: по три листа на каждый
полный viewport (секции/состояния страницы, услуги, форма) и два Hero-листа
для коротких viewport. HTML с встроенными свежими PNG снимается Chromium;
дополнительного image-пакета нет. Подписи содержат секцию, состояние и размер.
Большие desktop-снимки уменьшаются по ширине листа максимум до 960px;
оригиналы доступны в `build/visual-review/captures/` и приложениях отчёта.

Подготовительный проект очищает только `build/visual-review`, исключая старые
снимки. Teardown выполняется и после упавших сравнений/инвариантов. Если
сценарий не дошёл до снимка, лист помечается «НЕПОЛНЫЙ ПРОГОН», проверка его
комплектности падает, а доступные снимки и сам лист сохраняются.
Для полного комплекта используйте полный `test:visual` или `test:visual:review`;
выбор отдельных тестов оставит некоторые листы неполными.

Обычный запуск не создаёт отсутствующие эталоны (`updateSnapshots: none`).
В Linux CI отсутствие конкретного эталона пропускает **только сравнение**:
сначала выполняются действия/проверки состояния и сохраняется свежий PNG,
затем screenshot-тест получает `skip` с причиной. Существующие Linux-эталоны
сравниваются; несовпадение остаётся ошибкой. Инварианты и контактные листы
выполняются независимо. Windows-эталоны не используются вместо Linux.

CI устанавливает Node Chromium после сборки Preview, проверяет TypeScript и
запускает `npm run test:visual`. Артефакт `final-dev4-visual-review-linux`
содержит контактные листы, оригиналы, HTML/JSON-отчёт, диффы и traces при ошибках;
загрузка артефакта выполняется с `if: always()`.

При изменении вида: выполните `npm run test:visual` → посмотрите actual/expected/diff
через `npx playwright show-report build/visual-report` → подтвердите изменение
→ `npm run test:visual:update` → снова посмотрите листы и прогоните сравнение
→ закоммитьте только утверждённые эталоны. Скрипты ничего не публикуют.

## Проверено без браузера и ограничения

Зависимость `@playwright/test` закреплена на `1.63.0`, stable npm на 2026-09-12.
Источник версии: [npm registry](https://registry.npmjs.org/@playwright/test/latest),
повторная проверка командой `npm view @playwright/test version` и установленным
`package-lock.json`. Поведение снимков сверено с
[официальным руководством](https://playwright.dev/docs/test-snapshots) и типами
установленного Playwright; порядок teardown — с
[документацией проектов](https://playwright.dev/docs/test-projects#teardown)
и конфигурацией набора.

Браузер в песочнице не запускался: проверка ограничена `tsc --noEmit` и
`playwright test --list`: обе команды завершились с кодом 0. Перечислены
**485 тестов в 6 файлах**: 244 screenshot-сценария, 118 регистраций 11
инвариантов владельца, 90 регистраций 9 групп из Python, подготовка каталога
и 32 контактных листа. По условиям ширины/высоты предусмотрен 31 пропуск:
7 меню, 13 инвариантов владельца и 11 Python-проверок; это не результаты запуска.
Применимых числовых/функциональных проверок — 184 из 208 регистраций.
Скриншоты/эталоны не созданы, визуальная приёмка
ожидает запуска владельцем. Набор ограничен Chromium, DPR 1 и указанными
viewport. Windows/Linux рендерят шрифты по-разному; утверждение эталонов
проводится отдельно на каждой платформе. Рамки фото не доказывают одинаковый
масштаб лиц; эстетика и корректность контента остаются за владельцем.
