# Критика писем офиса и план полировки

**Версия:** `EMAIL-CRITIQUE 0.1.0` · **Дата:** 2026-09-23 · **Статус:** критика + план, `EmailTemplates.gs` НЕ изменён
**Скилл:** `design:design-critique` (структурная критика: usability → visual hierarchy → consistency → accessibility).
**Материал:** `apps-script/src/EmailTemplates.gs` @ `1071f53`, превью `docs/email-previews/*.png` (new-lead, sla-first-attempt,
sla-escalation, все 4 комбинации 390/1024 × light/dark) + рендер исходного `apps-script/preview/out/new-lead.html`.

## Design Critique: письма офиса (новая заявка / SLA / эскалация)

### Overall Impression

Структура письма правильная (шапка с wordmark → белая карточка → подписанные строки → CTA → футер), бренд-токены
взяты из `site/styles.css` корректно, 44px кнопки и dark-mode через `prefers-color-scheme` — всё сделано по
современным гайдам почтовой вёрстки. Главная проблема — не в структуре, а в **трёх конкретных, вычисленных** дефектах:
один — WCAG-провал контраста, один — WCAG-провал контраста UI-компонента, один — визуальная иерархия трёх CTA без
сигнала «что первое». Все три исправлены в `email-v2.html` без новых цветов — только перестановка существующих
токенов `EMAIL_BRAND_`.

### Usability

| Finding | Severity | Recommendation |
|---|---|---|
| Секондари-кнопка «Написать в WhatsApp» в light-теме — почти невидимый tap-target: заливка `#ffffff` на белой карточке `#ffffff`, единственная граница — контурный `#d1d5db` | 🔴 Critical | дать заливку, отличную от карточки (`#f6f1e8`, уже бренд-токен `--bg-cream`) + границу с реальным контрастом (`#6b7280`) — см. §Accessibility |
| Та же кнопка в dark-режиме НЕ переопределена медиа-запросом — остаётся плоским белым прямоугольником на тёмной карточке | 🟡 Moderate | добавить `.btn-secondary` в блок `@media (prefers-color-scheme: dark)`: `background:#1c232c; border-color:#9ca3af` |
| Гориз. 8px-спейсер между «Позвонить»/«WhatsApp» — единственный источник зазора; при переносе на новую строку (≤420px) зазор берётся из побочного line-height, не из явного отступа | 🟢 Minor | `margin-top:8px` прямо на ссылке WhatsApp — гарантирует зазор независимо от почтового клиента |

### Visual Hierarchy

- **Что цепляет взгляд первым:** сейчас — жёлто-золотая «Позвонить» ДА, но следом взгляд утыкается в тёмно-красную
  «Открыть заявку» — два визуально «громких» залитых CTA на одном письме без сигнала последовательности действий.
- **Что должно быть первым:** «Позвонить» — с него стартует SLA-таймер (design §5.5). «Открыть заявку» — это
  административный шаг (проставить статус/следующий шаг), не первое действие офиса.
- **Fix:** «Открыть заявку» → outline-кнопка (`background:transparent; border:1px solid #8a1f1f; color:#8a1f1f`),
  тот же 44px/8px radius. Текст-на-белом контраст 9.1:1 — читаемость не теряется, теряется только «второй loud
  CTA», что и требовалось.
- **Эскалация неотличима от рутинного SLA-напоминания:** `sla-first-attempt` и `sla-escalation` — **пиксель в
  пиксель один и тот же шаблон** (`renderShortLeadEmail_`), различается только текст заголовка. Эскалация уходит
  владельцу (`gambarian@gmail.com` + `alex@adfix.co.il`, design §12.2) при СРЫВЕ SLA — более серьёзное событие, чем
  обычное напоминание офису, но одинаковая чёрная шапка + золотой акцент не даёт визуального приоритета при
  сканировании инбокса.

### Consistency

| Element | Issue | Recommendation |
|---|---|---|
| Цвет футера (`ink3 #6b7280`) | Одинаковый inline-цвет и на карточке (где ОК), и на кремовом фоне страницы (где проваливает AA) — не различает поверхность | Оставить `ink3` для текста НА карточке, `ink2` — для текста на `bg-outer` (кремовом/тёмном фоне) |
| Кнопки CTA | «Позвонить» и «Открыть заявку» — обе filled, разного цвета, одинакового веса | Один filled (primary), остальные outline/ghost — см. Visual Hierarchy |

### Accessibility

**Contrast — вычислено (WCAG relative-luminance formula), не на глаз:**

| Пара | Где | Контраст | Порог | Результат |
|---|---|---|---|---|
| Футер `#6b7280` на `#f6f1e8` (кремовый фон страницы) | light, все 3 шаблона | **4.3 : 1** | 4.5:1 (обычный текст) | 🔴 **FAIL** |
| Футер `#9ca3af` на `#151b22` (карточка, dark override) | dark | 6.8 : 1 | 4.5:1 | ✅ PASS (без изменений) |
| Метки строк `#6b7280` на `#ffffff` (карточка) | light | 4.84 : 1 | 4.5:1 | ✅ PASS, но запас всего +0.34 — на грани |
| Граница WhatsApp-кнопки `#d1d5db` на `#ffffff` | light | **1.24 : 1** | 3:1 (WCAG 1.4.11, non-text UI contrast) | 🔴 **FAIL** — кнопка визуально не существует как компонент |
| Текст «Позвонить» `#14191f` на `#f0ae1f` | оба режима | 9.16 : 1 | 4.5:1 | ✅ PASS |
| Текст «Открыть заявку» (было: белый на `#8a1f1f`) | оба режима | 9.14 : 1 | 4.5:1 | ✅ PASS |
| Текст «Открыть заявку» (стало: `#8a1f1f` на белом, outline) | light | 9.14 : 1 (симметрично) | 4.5:1 | ✅ PASS |
| Футер, ПОСЛЕ фикса: `#4b5158` на `#f6f1e8` | light | **7.14 : 1** | 4.5:1 | ✅ PASS с запасом |

**Touch targets:** все CTA уже ≥44px высотой (line-height трюк) — соответствует платформенным рекомендациям, не
трогаем.

**Text readability:** 15px для значений, 12px для меток, `line-height` не задан явно на строках-метках — при
переносе длинного значения (см. Usability/wrapping ниже) метка и первая строка значения не всегда выравниваются
по базовой линии (`valign="top"` на метке уже смягчает это).

### Mobile wrapping — длинные значения

Оригинальный fixture (`render-previews.mjs`) использует короткое имя «Мария Соколова» — ни разу не проверяет перенос.
В `email-v2.html` подставлено намеренно длинное составное имя `Александра Никифорова-Штейнберг` и более длинный
email `a.nikiforova-steinberg@example.com`: при 390px оба переносятся на 2 строки чисто, без обрезки и без наезда
на метку слева (скриншоты `email-v2-390-*.png`). Правок разметки для этого не потребовалось — `<td>` значения уже
без `white-space:nowrap`, перенос работал и в v1; риск был не подтверждён на практике только потому, что testset
не содержал длинных имён. Рекомендация — **добавить длинное имя в набор фикстур** `render-previews.mjs`, чтобы
это перестало быть слепой зоной на будущих правках шаблона (не сделано в этой задаче — design-only, `.mjs` не
трогаем).

### What Works Well

- 44px кнопки, dark-mode через `prefers-color-scheme` (не жёсткий переключатель), preheader (`display:none` div) —
  всё по актуальным гайдам почтовой вёрстки.
- `escapeHtml_` применяется ко всем полям до вставки в HTML — инъекция вида `<script>`/`=1+1` не рендерится как код
  (`test/email-templates.test.mjs` уже это покрывает).
- Текстовая версия (`text:` в `renderNewLeadEmail_`/`renderShortLeadEmail_`) не забыта — почтовые клиенты без HTML
  получают эквивалентную информацию.
- Единая палитра между письмами, сайтом (`site/styles.css`) и (теперь) дашбордом «Сводка»/«Сегодня» — одна
  зрительная система для всего мини-CRM.

### Priority Recommendations — top 5, с точными значениями

1. **Контраст границы secondary-кнопки (WCAG 1.4.11, 1.24:1 → цель ≥3:1).** `border:1px solid #d1d5db` →
   `background:#f6f1e8; border:1px solid #6b7280` (light); добавить dark-override `background:#1c232c;
   border-color:#9ca3af`. Это единственный **блокирующий** accessibility-дефект в тройке писем.
2. **Контраст футера на кремовом фоне (WCAG AA text, 4.3:1 → 7.14:1).** `color:#6b7280` → `color:#4b5158` в
   inline-стиле `<span class="email-text-muted">` для ВСЕХ трёх шаблонов (только light — dark override уже верный).
3. **Иерархия CTA: два filled-CTA одного визуального веса → один filled + один outline.** «Открыть заявку»:
   `background:#8a1f1f;color:#fff` → `background:transparent;border:1px solid #8a1f1f;color:#8a1f1f`. «Позвонить»
   остаётся единственной filled/loud кнопкой — SLA стартует с неё.
4. **Эскалация визуально = рутинный SLA-реминдер.** Добавить wine-бейдж над заголовком ТОЛЬКО в
   `renderSlaEscalationEmail_`: `<span style="background:#8a1f1f;color:#fff;font-size:11px;font-weight:700;
   letter-spacing:.08em;text-transform:uppercase;padding:4px 10px;border-radius:999px;">Эскалация</span>` —
   существующий цвет, не новый.
5. **Гарантированный вертикальный зазор кнопок при переносе.** `<span style="width:8px">` (только горизонтальный)
   → добавить `margin-top:8px` на ссылку WhatsApp, чтобы перенос на новую строку (узкие клиенты/крупный шрифт
   пользователя) не слипался с кнопкой «Позвонить».

Пункты 1-3 и 5 применены в `email-v2.html` (только новая заявка — задание ограничено этим шаблоном). Пункт 4
(бейдж эскалации) НЕ применён нигде — это правка `renderSlaEscalationEmail_`, отдельного шаблона, не входящего в
эту часть задания; зафиксирован здесь как следующий шаг.
