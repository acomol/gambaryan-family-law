# Мини-CRM заявок lp.gambarian.com — проект

**Версия:** `MINI-CRM-DESIGN 0.1.0` · **Дата:** 2026-09-23 · **Статус:** на утверждении владельцем

Таблица: `Leads_web_LP` (`1_jhfr7ucoKkbrwWlUQoS9wyw7uHYhe_oOutKpTlcoV4`, владелец gambarian@gmail.com).
Эталон подхода: CRM Assuta (ADR-060/061, `feature/luxemed-new-lending`: `docs/CRM-CONSOLIDATION-DESIGN-2026-06.md`,
`docs/SHEETS-APPS-SCRIPT-2026-06.md`). Берём схему и код, **не данные** — это другой клиент.

## 0. Цель и границы

- Таблица — рабочее место офиса: человек видит заявку, звонит, ставит статус, пишет следующий шаг.
- Скрипт следит за сроками и пишет офису, когда заявка ждёт или обещание клиенту просрочено.
- Таблица — **не единственная копия** лида: сервер хранит заявку в KV + D1 + R2 (`docs/LEAD-PIPELINE.md`,
  после переноса эталона). Потеря строки в таблице не теряет лида.
- Вне границ (фаза 2): отправка «Клиент — договор» в Google Ads как офлайн-конверсия (§11).

## 1. Как течёт заявка

```
форма lp → /api/lead (сервер: KV+D1+R2) → Albato: Create/update a row по submission_id → лист «Заявки»
                                                                              ↓ (каждые 5 мин)
                                                          Apps Script tick(): номер, дата по Израилю,
                                                          ссылки WhatsApp/звонок, «Откуда»,
                                                          слияние исправлений, уведомления, SLA
офис: статус / следующий шаг → installable onEdit: штамп времени, журнал, проверка обязательных полей
08:30 вс–чт: дайджест · вс 08:00: недельная сводка
```

**Почему по расписанию, а не «при появлении строки».** Albato пишет в таблицу через Sheets API, а записи через
API не запускают ни простой, ни устанавливаемый `onEdit`: «Script executions and API requests don't cause
triggers to run» ([Google, triggers](https://developers.google.com/apps-script/guides/triggers)). Поэтому новые
строки замечает только проверка по времени.

## 2. Листы

| Лист | Для кого | Что |
|---|---|---|
| **Заявки** | офис | одна строка = одна заявка; слева поля офиса, справа свёрнутая техника |
| **Сегодня** | офис | только формулы: что сделать сегодня (новые, просроченные шаги, консультации сегодня, повторный звонок) |
| **Сводка** | владелец | воронка, доля договоров, время до первого контакта, источники, месяцы |
| **Настройки** | владелец/ADFIX | статусы и цвета, причины отказа, сотрудники, рабочие часы, праздники, пороги SLA, получатели |
| **Журнал** | ADFIX | что сделал скрипт: уведомления, слияния, ошибки, смены статусов. Без телефонов и имён — только № заявки |

Лист сейчас называется «2026». Переименовываем в **«Заявки»** до подключения Albato (после — сломает маппинг).
Разделение по годам — фильтром, не вкладками: иначе каждый январь перенастраивать Albato.

## 3. Лист «Заявки»: колонки

Колонки скрипт ищет **по заголовку** (`colByHeader_`, эталон Assuta), не по букве: порядок можно менять.

### 3.1 Зона офиса (слева, первый экран)

| # | Заголовок | Кто пишет | Правило |
|---|---|---|---|
| 1 | **№** | скрипт | `G-0001`… по порядку прихода; им называем заявку в разговорах и уведомлениях |
| 2 | **Статус** | офис | выпадающий список (§4); пусто → скрипт ставит «Новая» |
| 3 | **Получена** | скрипт | дата и время по Израилю из `submitted_at` (`Utilities.formatDate`, Asia/Jerusalem) |
| 4 | **Имя** | Albato | из формы |
| 5 | **Телефон** | Albato | формат «обычный текст» — иначе `+972…` превращается в число/ошибку (урок Assuta) |
| 6 | **Связаться** | скрипт | две ссылки: «Позвонить» (`tel:`) и «WhatsApp» (`wa.me/…`) |
| 7 | **Email** | Albato | из формы |
| 8 | **Ответственный** | офис | список из «Настроек» |
| 9 | **Попыток дозвона** | офис | число 0–5 |
| 10 | **Следующий шаг** | офис | дата: когда вернуться к клиенту |
| 11 | **Консультация** | офис | дата и время консультации |
| 12 | **Причина закрытия** | офис | список; обязателен для закрытых без договора |
| 13 | **Комментарий** | офис | свободный текст; **без подробностей дела** (§8) |
| 14 | **Откуда** | скрипт | «Google Ads» (есть gclid/gbraid/wbraid), иначе `utm_source`, иначе «Прямой» |

### 3.2 Служебные (скрыты, защита «с предупреждением»)

`Первый контакт` · `Статус изменён` · `Договор` (дата) · флаги уведомлений `notified_new`, `notified_sla1`,
`notified_sla2`, `notified_consult` · `merged_into` — пишет только скрипт.

### 3.3 Техника от Albato (справа, группа свёрнута, защита «с предупреждением»)

`submission_id` · `corrects_submission_id` · `submitted_at` · `landing_path` · `referrer_host` · `utm_source` ·
`utm_medium` · `utm_campaign` · `utm_id` · `utm_term` · `utm_content` · `gclid` · `gbraid` · `wbraid` · `fbclid` ·
`form_id` · `landing_language` · `event_name` · `source_system` · `schema_version` · `schema_date`.

Защита «с предупреждением» (`Protection.setWarningOnly(true)`) не мешает Albato писать через API, но
предупреждает человека, если он правит машинные колонки.

## 4. Статусы

| Статус | Группа | Цвет строки | Офис обязан заполнить | Что делает скрипт |
|---|---|---|---|---|
| **Новая** | открыта | жёлтый | — | уведомление сразу; SLA-напоминания (§5.3) |
| **Не дозвонились** | открыта | оранжевый | «Попыток дозвона», «Следующий шаг» | в дайджесте на дату шага; после 3 попыток и 5 дней — «предлагаю закрыть» |
| **В работе** | открыта | голубой | «Следующий шаг» | в дайджесте на дату шага |
| **Консультация назначена** | открыта | сиреневый | «Консультация» | напоминание ответственному утром дня консультации |
| **Консультация проведена** | открыта | синий | «Следующий шаг» | в дайджесте на дату шага |
| **Клиент — договор** | закрыта ✓ | зелёный | — | ставит дату «Договор»; строка в сводку |
| **Отказ** | закрыта | серый | «Причина закрытия» | — |
| **Дубль / спам** | закрыта | серый, зачёркнуто | — | исправления контактов скрипт сливает сам (§5.4) |

Причины закрытия: «Не дозвонились (3+ попытки)» · «Выбрал другого юриста» · «Дорого» · «Передумал» ·
«Не наш профиль» · «Другое (в комментарии)».

Цвет — условное форматирование по статусу на всю строку. Поверх — **красная рамка** на ячейке, если обязательное
поле статуса пустое (например «Консультация назначена» без даты) или «Следующий шаг» в прошлом у открытой заявки.

## 5. Автоматизация (Apps Script, привязан к таблице)

### 5.1 Триггеры

| Триггер | Когда | Функция |
|---|---|---|
| время | каждые 5 минут | `tick()` — новые строки, уведомления, SLA |
| время | ежедневно 08:30, вс–чт | `dailyDigest()` |
| время | вс 08:00 | `weeklySummary()` |
| устанавливаемый `onEdit` | правка человеком | штамп «Статус изменён» / «Первый контакт» / «Договор», журнал, проверка обязательных полей |
| `onOpen` | открытие | меню «CRM»: «Проверить сейчас», «Тест уведомления», «Архивировать закрытые…» |

Разрушающие действия (архив, удаление тест-строк) — **только из меню**, никогда по таймеру (правило Assuta).

### 5.2 `tick()` по шагам

1. `LockService.getScriptLock().tryLock(20000)` — два запуска не пересекаются; не взял замок → выход.
2. Для строк без `№`: присвоить номер, «Получена», «Связаться», «Откуда», пустой статус → «Новая», телефон как текст.
3. Строки с `corrects_submission_id` → слияние (§5.4).
4. «Новая» без `notified_new` → уведомление о новой заявке → флаг `notified_new` = время.
5. SLA по рабочим минутам (§5.3) → уведомления → флаги.
6. Итог — одна строка в «Журнал» только если что-то произошло.

Флаг ставится **после** успешной отправки; отправка и флаг — под одним замком. Повторный запуск не шлёт дубль.

### 5.3 Сроки (SLA) — только рабочее время

Рабочие часы из «Настроек», по умолчанию как на сайте: вс–чт 09:00–18:00, Asia/Jerusalem
(`site-addons/action-bar/action-bar.js:26-31`). Праздники — список дат в «Настройках». Время считается
**в рабочих минутах**: заявка в пятницу вечером «ждёт» с воскресенья 09:00.

| Условие | Кому | Когда |
|---|---|---|
| Новая заявка | офису | сразу; ночью и в выходные — тихое сообщение (без звука) |
| «Новая» 30 рабочих минут без контакта | ответственному / офису | один раз |
| «Новая» 2 рабочих часа без контакта | владельцу | один раз (эскалация) |
| консультация сегодня | ответственному | в дайджесте 08:30 |

Ориентир: ответ в первые 5–30 минут в разы повышает шанс дозвониться; в среднем компании отвечают за 42 часа
(исследования MIT/InsideSales и HBR, пересказ: ainora.lt, 2026 — вторичный источник).

### 5.4 Исправление контактов

Форма после отправки позволяет исправить имя/телефон/email — придёт вторая строка с `corrects_submission_id`.
Скрипт: переносит новые контакты в исходную строку, старые пишет в «Комментарий» («контакты исправлены
ДД.ММ ЧЧ:ММ, было: …»), вторую строку помечает «Дубль / спам» + `merged_into`. Статус исходной не трогает.
Если исходной строки нет (ещё не пришла) — ждёт следующего tick, после 24 ч — оставляет как есть и пишет в журнал.

### 5.5 Сообщения (минимум данных)

Новая заявка: `Новая заявка G-0012 · Иван · +972 50-123-4567 · 10:42 · Google Ads` + ссылка на строку.
SLA: `G-0012 ждёт ответа 30 мин (ответственный: …)`. В сообщениях **нет** email, UTM, комментариев и подробностей.

Дайджест 08:30: новые за ночь · ждут первого звонка · консультации сегодня · просроченные шаги ·
«предлагаю закрыть». Пустые разделы не показываются; если всё пусто — дайджест не отправляется.

Неделя (вс 08:00, владельцу): заявок · дошли до консультации · договоров · отказов с причинами ·
медиана времени до первого контакта · Google Ads против остального.

## 6. Каналы уведомлений

| Канал | Для чего | Что нужно |
|---|---|---|
| **Telegram** — закрытая группа офиса + бот | новая заявка, SLA, дайджест | бота создаёт владелец (@BotFather); токен и chat_id — в Script Properties, не в таблице |

| WhatsApp | не в первой версии | Cloud API: верификация бизнеса + платные шаблоны — отдельное решение |

Лимиты обычного Gmail: 100 получателей писем в сутки, 90 минут работы триггеров в сутки, 20 триггеров
на скрипт, 6 минут на запуск ([Google, quotas](https://developers.google.com/apps-script/guides/services/quotas)).
Нагрузка: tick каждые 5 мин ≈ 288 запусков × ~2–4 с ≈ 10–20 мин в сутки — в пределах.

## 7. Albato

Сценарий «Лиды с лендинга → Таблица + Email (LP Leads)» (bundle 389466), триггер «Gambarian lp- leads (prod)»:
1. Webhook: Incoming webhook — есть.
2. Parse JSON — **убрать**: наш payload плоский (у Assuta был `payload_json`).
3. **Google Sheets: Create/update a row**, лист «Заявки», поиск по `submission_id`; пишет только
   Имя/Телефон/Email и техническую зону. Колонки офиса и служебные — **не маппить**.
4. Webhook: Answer — 200.
Письмо на каждую заявку из Albato **не делаем** — уведомления в одном месте, в скрипте (без дублей).

## 8. Приватность и доступ

- Таблица с контактами людей, которые разводятся, — чувствительные данные; с 14.08.2025 действует
  Поправка 13 к израильскому закону о защите приватности (pearlcohen.com, iapp.org).
- **Доступ «все, у кого есть ссылка — редактор» закрыть до первой настоящей заявки** (решение владельца отложено).
  Оставить явных редакторов: владелец, офис, ADFIX.
- Скрипт ставится от аккаунта с **явным** доступом (не по ссылке) — иначе после закрытия ссылки он перестанет работать.
- В «Комментарий» — только ход работы, без обстоятельств дела.
- Хранение: закрытые заявки старше N месяцев — архив/обезличивание из меню (N решает владелец).
- Журнал «кто что изменил» — история версий Google; полноценного журнала просмотров у обычного Gmail нет — известный пробел.

## 9. Ограничения и риски

| Риск | Что делаем |
|---|---|
| Строку Albato могут пересортировать/удалить люди | поиск по `submission_id`, не по номеру строки; удаление — только из меню |
| Повтор заявки перезапишет исправленный человеком телефон | Albato маппит контакты; редкий случай, исправления офис пишет в «Комментарий» |
| Триггер тихо умер (владелец потерял доступ, квота) | дайджест приходит каждый рабочий день — его отсутствие видно; tick пишет heartbeat в «Настройки» |
| Telegram-токен утёк | в группе только № и контакт, без дела; токен меняется в @BotFather |
| Часы/праздники неверны | правятся в «Настройках», без кода |

## 10. Установка и проверка

1. Владелец утверждает проект и решения §12.
2. Код — в репозитории `apps-script/` (версионируется, как у Assuta); ставит Codex в браузере от выбранного аккаунта.
3. `setupCrm()` из меню — идемпотентно создаёт листы, заголовки, списки, цвета, защиту, группировку.
4. Albato: шаги §7 → тест-заявка «ТЕСТ» → строка → через ≤ 5 мин номер и сообщение в Telegram.
5. Проверки, которые могут упасть: повторная отправка того же `submission_id` не даёт второй строки и второго
   сообщения; исправление контактов сливается; «Новая» 31 рабочую минуту → одно напоминание, не два;
   ночная заявка → тихое сообщение; пустой дайджест не отправляется.
6. Тест-строки удаляются из меню; в журнале остаётся запись.
