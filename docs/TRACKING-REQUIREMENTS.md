# Требование: отслеживаемость всех действий

**Правило проекта:** каждое действие пользователя, которое можно считать шагом к
заявке, должно быть отслеживаемым. Прямых ссылок «наружу» без обёртки на сайте
быть не должно.

**Причина.** Прямая ссылка `wa.me` или `tel:` — уход со страницы. Событие
конверсии Google Ads не успевает уйти либо не отправляется вовсе, и рекламный
кабинет не видит лид, который фактически состоялся. Оптимизация кампаний идёт по
неполным данным: система учится на форме и не учится на звонках, хотя звонок —
основная цель практики.

Найдено на рынке (`docs/HERO-CTA-RESEARCH.md`): avivitmoskovich.co.il решает это
именно так — сначала `gtag('event','conversion',{...})`, и только в колбэке
редирект на `wa.me`. То есть проблема известна и решается обёрткой, а не
надеждой на автосбор.

---

## Что отслеживаем

| Действие | Где встречается | Событие |
| --- | --- | --- |
| Клик по телефону | hero, контакты, футер, ошибка формы, панель действий | `contact_click` · `method=phone` |
| Клик по WhatsApp | контакты, футер, ошибка формы, панель действий | `contact_click` · `method=whatsapp` |
| Клик по адресу → карты | карточки адвокатов, контакты, футер | `contact_click` · `method=google_maps` |
| Переход к форме по якорю | hero, шапка, карточки услуг, прецедент, панель | `form_anchor_click` |
| Отправка формы | блок контактов | `generate_lead` |
| Ошибка отправки формы | блок контактов | `form_error` |

## Как реализуется

**Разметка уже подготовлена.** На контактных ссылках стоит атрибут
`data-action` — точка подключения без правки вёрстки:

```html
<a href="tel:+972545490623" data-action="phone_click">054-549-0623</a>
<a href="https://wa.me/972545490623" data-action="whatsapp_click">…</a>
<a class="map-link" href="https://www.google.com/maps/…" data-action="map_click">…</a>
```

**Обёртка обязательна там, где происходит уход со страницы.** Порядок:
отправить событие → дождаться подтверждения или таймаута → выполнить переход.

- `tel:` — страница не выгружается, потеря хита не грозит, но в автосбор GA4
  событие не попадает вовсе: это не http-переход. Событие вешается вручную.
- `wa.me`, карты — переход на внешний домен. Если ссылка открывается в той же
  вкладке, хит может не успеть уйти. Либо `target="_blank"` (тогда страница не
  выгружается), либо задержка перехода до отправки события.
- Google Ads конверсия — отдельно от GA4-события, с `event_callback`.

## Конфигурация GTM

Триггер *Click — Just Links*, обязательно включить:

- **Wait for Tags** — 2000 мс. Документация Google Tag Manager: «wait until all
  tags have fired, or the specified timeout has elapsed».
- **Check Validation** — «Only fire tags when the link click is considered a
  valid action».

Условие по `Click URL`:

```
^tel:|^https?://(wa\.me|api\.whatsapp\.com)|google\.com/maps|waze\.com
```

Тег GA4 Event, единое событие `contact_click`, параметры:

| Параметр | Значение |
| --- | --- |
| `method` | Lookup Table по `Click URL`: `phone` / `whatsapp` / `google_maps` |
| `link_url` | `{{Click URL}}` |
| `link_text` | `{{Click Text}}` |
| `page_location` | `{{Page URL}}` |

В GA4 после внедрения: зарегистрировать `method` как **custom dimension** —
иначе параметр не появится в отчётах; отметить `contact_click` как **key event**.

**Не забыть про двойной учёт.** GA4 Enhanced Measurement уже считает переходы на
внешние домены обезличенным событием `click`. Либо всегда фильтровать отчёты по
`contact_click`, либо отключить «Outbound clicks», если других внешних ссылок на
сайте нет.

## Чего сейчас нет

- **Обёрток нет ни на одной ссылке** — стоят только атрибуты `data-action`.
  Реализация ждёт подключения GTM/GA4 к этому домену.
- **Форма никуда не отправляет.** `submitLead()` в `site/app.js` — заглушка,
  возвращает успешный Promise без запроса. Событие `generate_lead` вешать не на
  что, пока не подключён приём заявок (Netlify Forms, вебхук в Make/n8n или CRM).
- **Колл-трекинг не подключён.** Статический `tel:` в разметке не даёт разбивки
  звонков по источникам. Найдено на рынке: Morgan & Morgan показывает номер, но
  `href="tel:"` в исходном HTML нет вовсе — номер подставляется скриптом, почти
  наверняка динамическая подмена под колл-трекинг. Если понадобится считать
  звонки по кампаниям, статической разметки будет мало.

## Проверка после внедрения

GTM Preview + GA4 DebugView, прокликать все типы ссылок **на реальном мобильном
устройстве**: переход в приложение WhatsApp и открытие диалера в эмуляции
DevTools не воспроизводятся.
